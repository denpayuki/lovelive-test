# 部署到 Cloudflare Pages — 零基础指南

本指南会手把手教你把这个网站发布到互联网上，全程免费，不需要任何编程知识。

---

## 你需要准备什么

1. **一个 GitHub 账号** — 如果没有，去 https://github.com 注册一个（免费）
2. **一个 Cloudflare 账号** — 如果没有，去 https://dash.cloudflare.com/sign-up 注册一个（免费）
3. **这个项目的代码** — 需要上传到你的 GitHub 仓库里

---

## 第一步：把代码上传到 GitHub

如果你的代码已经在 GitHub 上了，跳到第二步。

1. 登录 GitHub，点击右上角的 **+** 号，选择 **New repository**（新建仓库）
2. 给仓库起个名字，比如 `shiny-mbti`
3. 其他选项保持默认，点击 **Create repository**（创建仓库）
4. 按照页面上显示的指引，把本地代码推送上去（如果你不确定怎么操作，可以找身边懂 Git 的朋友帮忙）

---

## 第二步：在 Cloudflare 创建项目

1. 登录 Cloudflare 控制台：https://dash.cloudflare.com
2. 在左侧菜单中找到 **Workers 和 Pages**，点击进入
3. 点击页面上的 **创建** 按钮
4. 选择 **Pages** 标签页
5. 点击 **连接到 Git**

---

## 第三步：连接你的 GitHub 仓库

1. 第一次使用会提示你授权 Cloudflare 访问你的 GitHub，点击 **授权** 即可
2. 在仓库列表中找到你刚才上传的 `shiny-mbti` 仓库，选中它
3. 点击 **开始设置**

---

## 第四步：配置构建设置

这一步非常关键，请按照下面的内容**逐项填写**：

| 设置项 | 填写内容 |
|---|---|
| **项目名称** | 保持默认，或者改成你喜欢的名字（这会成为你网址的一部分） |
| **生产分支** | `main`（通常默认就是这个） |
| **框架预设** | 选择 **无 / None** |
| **构建命令** | `npm run build` |
| **构建输出目录** | `dist` |

其他选项不用动，保持默认。

---

## 第五步：点击部署

1. 确认上面的设置无误后，点击 **保存并部署**
2. 等待几分钟，Cloudflare 会自动安装依赖、构建项目、发布网站
3. 构建过程中你会看到实时日志，如果一切顺利，最后会显示 **部署成功**

---

## 第六步：访问你的网站

部署成功后，Cloudflare 会给你一个免费的网址，格式类似：

```
https://你的项目名.pages.dev
```

点击这个链接，就能看到你的网站了！

---

## 后续更新

以后每次你把新代码推送到 GitHub 的 `main` 分支，Cloudflare 会**自动重新构建和部署**，不需要你手动操作。

---

## 可选：绑定自定义域名

如果你有自己的域名（比如 `example.com`），可以绑定到这个项目上：

1. 在 Cloudflare Pages 项目页面，点击 **自定义域** 标签
2. 点击 **设置自定义域**
3. 输入你的域名，按照提示添加 DNS 记录
4. 等待 DNS 生效（通常几分钟到几小时）

---

## 常见问题

### 构建失败了怎么办？

- 检查构建日志中的错误信息，最常见的原因是 Node.js 版本不兼容
- 在 Cloudflare Pages 项目的 **设置 > 环境变量** 中，添加一个变量：
  - 变量名：`NODE_VERSION`
  - 值：`20`
- 然后重新触发部署

### 网站打开后页面空白？

- 检查构建输出目录是否填的 `dist`（不是 `build` 或其他）
- 检查构建命令是否填的 `npm run build`

### 点击"角色图鉴"后刷新页面显示 404？

- 这个问题已经处理好了。项目中的 `_redirects` 文件会确保所有路径都正确指向首页，Cloudflare Pages 会自动识别它
